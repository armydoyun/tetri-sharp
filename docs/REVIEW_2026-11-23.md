# 기능 · UI/UX 깐깐 평가 2차 (2026-11-23)

1차 평가(`docs/REVIEW_2026-11-22.md`)의 항목을 모두 정리한 뒤, 그 사이에 들어온 것들을 다시 본다.
업적 · 랭크 · CPU 성향과 두 수 앞보기 · 내 규칙 여러 개 · 첫 화면 재배치 · 컨트롤 정리(`css/controls.css`) · 짧은 판 처리 · 휴대폰 가로 설정.

배포본을 빌드해 데스크톱 1280×800, iPhone 13 세로(390×664), iPhone 13 가로(750×342)에서
첫 화면 · 도움말 · 연습 · 퍼즐 · 기록 · 업적 · 설정 여섯 탭 · 규칙 편집 · CPU 대전 · 오늘의 도전 · 플레이 · 일시정지 · 결과 · 리플레이 · CPU 대전 플레이를 찍고(74장),
새 기능 코드(`js/storage/achievements.js`, `js/modes/ranks.js`, `js/storage/rule-slots.js`, `js/ai/bot.js`, `js/storage/backup.js`, `js/main.js` 결과 부분)를 읽었다.
콘솔 오류 · 경고는 없었다.

**총평:** 1차 때의 "누를 수 없는 버튼 · 읽을 수 없는 글자"는 사라졌고, 컨트롤 구조도 테스트가 지킨다.
이번에 남은 문제는 **자리만 차지하고 아무것도 없는 칸**이다. 원칙 2("상태가 바뀌어도 자리를 지킨다")를 지키려고 비워 둔 자리가
휴대폰에서는 그대로 구멍이 된다 — CPU 대전 보드가 3분의 1이 줄어드는 것이 가장 크다.
기능 쪽은 **새로 붙인 것들이 "규칙"과 맞물리는 곳**(Custom 규칙의 업적 · 랭크, 프리셋 덮어쓰기)과 **짧은 판 판정이 아직 좁은 것**이 걸린다.

심각도: **치명** = 못 쓰거나 잘못 씀 · **높음** = 크게 불편하거나 잃는 것이 있음 · **보통** = 거슬림·일관성 · **낮음** = 다듬기.
번호는 1차에 이어 붙인다(F20~, U32~).

## Part 1. 기능

### 1-1. 잘못 동작하거나 잃는 것이 있는 것

| # | 심각도 | 기능 | 문제 |
|---|---|---|---|
| F20 | 높음 | 규칙 편집 "프리셋에서 시작" | Modern · Retro · Arcade를 누르면 **지금 고른 내 규칙을 확인 없이 덮어쓴다**(`js/ui/rules.js` 412행, 되돌리기 없음). 내 규칙을 10개까지 이름 붙여 두게 해 놓고, 한 번 잘못 누르면 공들인 조합이 사라진다. 새 칸으로 만들거나, 덮어쓰기 전에 묻거나, 바로 되돌리기를 줘야 한다. |
| F21 | 높음 | 짧은 판 판정(F11 후속) | "피스 10개 미만 · 10초 안"만 짧은 판으로 본다. 하드 드롭을 연타하면 **1초에 12피스**를 놓고 막히는데, 그러면 PPS 11.80, 공유 가능, "마지막 판" 덮어쓰기, **"추천 연습 · O 피네스"**까지 그대로 나온다(데스크톱 결과 화면). 판정 기준을 "줄을 하나도 못 지우고 몇 초 안에 막힘"처럼 실제 의미에 맞춰야 한다. |
| F22 | 보통 | 업적 · 랭크와 Custom 규칙 | 모드 업적(`inMode`)은 규칙을 보지 않는다. Custom에서 고정 지연 · 줄 삭제 지연 · 등장 지연을 0으로 두면 Sprint가 쉬워지는데 "Sprint 1분"과 랭크가 그대로 인정된다(랭크도 Custom 기록표에 그대로 붙는다). 업적 · 랭크는 기본 규칙(Modern 등)에서만 주거나, Custom이면 "Custom 기준"이라고 밝혀야 한다. |
| F23 | 보통 | 백업 | 백업 키에 **CPU 성향(`versus:style`)이 빠져 있다**(`js/storage/backup.js` `BACKUP_KEYS`). 백업을 불러오면 전적은 오는데 고른 성향은 균형으로 돌아간다. |
| F24 | 보통 | CPU 난이도 사다리 | 두 수 앞보기 뒤로 **보통+ → 어려움이 40판 중 40판** 차이가 됐다(이전 27판). 그 아래 단계 사이(쉬움→쉬움+→보통→보통+)는 완만한데 여기서만 벽이다. 어려움의 속도 · 실수 확률을 낮추거나 사이에 한 단계를 두어야 한다. |

### 1-2. 부족한 것

| # | 심각도 | 기능 | 문제 |
|---|---|---|---|
| F25 | 보통 | 기록 지우기 | 기록 · 리플레이 · 업적을 지울 방법이 없다. 설정의 "전체 설정 초기화"는 설정만 되돌린다(그런데 이름만 보면 다 지울 것 같다 — U40). 공용 PC에서 남의 기록을 치우거나 내 기록을 새로 시작할 수 없다. 데이터 탭에 "기록 지우기"(확인 필수)가 필요하다. |

## Part 2. UI/UX

### 치명

| # | 화면 | 문제 |
|---|---|---|
| U32 | 휴대폰 CPU 대전 플레이 | **보드가 358px → 238px로 줄어든다.** CPU 상황 줄(`#versus-panel`)은 휴대폰에서 한 줄(이름 · 보낸 줄 · 받을 쓰레기)만 보이는데 높이를 113px 차지하고, 그 아래로 빈칸이 생긴다. 같은 화면 Sprint와 비교하면 보드 면적이 44% 줄어 CPU 대전이 휴대폰에서 가장 하기 힘든 모드가 된다. CPU 보드를 숨긴 화면에서는 패널 높이를 한 줄로. |

### 높음

| # | 화면 | 문제 |
|---|---|---|
| U33 | 첫 화면 규칙 블록(모든 크기) | Custom이 아닐 때 내 규칙 줄(`#rule-slot-row`)이 `visibility: hidden`으로 자리만 차지해, **규칙 탭과 설명 사이에 빈 칸**이 생긴다(휴대폰에서 약 100px). 설명이 탭과 떨어져 페이지 맨 아래 따로 떠 보인다. 설명을 탭 바로 아래로 올리고 내 규칙 줄을 그 아래에 두거나, Custom이 아닐 때는 줄 대신 "Custom을 고르면 내 규칙을 저장해요" 같은 안내로 채운다. |
| U34 | 첫 화면 모드 카드(휴대폰 · 가로에서 뚜렷) | 번호 없는 모드 줄(`.menu-row-stacked`)은 "최고 기록" 칸이 비어 있어도 둘째 줄과 칸 사이 간격이 남아, **이름 · 설명이 카드 위쪽에 붙고 아래가 빈다.** 기록이 없는 처음 사용자는 모든 카드가 이렇게 보인다. 오른쪽 화살표만 가운데 있어 더 어긋나 보인다(UI 검수는 화살표만 재서 못 잡았다). |
| U35 | CPU 대전 대화상자 | 아래 **"닫기" 버튼만 대화상자 폭 전체로 늘어난다.** 알림 칸을 `hidden`으로 빼서 발(footer) 격자의 첫 칸(1fr)을 닫기 버튼이 차지한다(`js/ui/versus.js` 12행). 다른 대화상자는 오른쪽 작은 버튼이다. |

## 먼저 손볼 다섯 가지

1. **U32** 휴대폰 CPU 대전 보드 — 한 모드를 통째로 불편하게 만든다.
2. **U33 · U34 · U35** 첫 화면 · 대화상자의 빈 칸 — 처음 여는 사람이 가장 먼저 보는 화면이다. 세 개 모두 원인이 "자리만 차지하는 빈 요소"라 함께 고치고, UI 검수에 "보이는 내용 없이 높이만 차지하는 칸" 검사를 더한다.
3. **F20** 프리셋 덮어쓰기 — 사용자가 만든 것을 잃는다.
4. **F21** 짧은 판 판정 — 1차에서 고친 것이 실제 연타 판에서는 안 걸린다.
5. **F22 · F24** 업적 · 랭크의 규칙 기준, CPU 난이도 사다리 — 새 기능의 신뢰도.
