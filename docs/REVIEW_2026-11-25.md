# 앱 검수 5차 (2026-11-25) — 기능 · UI · UX · 게이머

4차 평가(`docs/REVIEW_2026-11-24-4.md`) 뒤에 퍼즐 만들기 1~4단계, 다듬기, 리팩토링(main.js 나누기)이 들어왔다.
이번 검수는 기능이 맞게 도는지와 함께 **UI 디자이너 · UX 디자이너 · 게이머** 세 관점에서 아쉬운 점을 찾는다.

## 어떻게 봤나

| 단계 | 한 일 |
|---|---|
| 1 · 자동 점검 | 기존 UI 검수 순회(`runScenarios`: 모든 화면·대화상자·탭·드롭다운·슬라이더 끝값)를 **8가지 조합**에서 돌렸다. 조합은 1440×900 · 1280×720 · 1280×800 · 768×1024 · 375×667 · 360×740 · 844×390(가로)이고, 한국어/영어, 라이트/다크, 동작 줄이기, 터치를 섞었다. 같은 순회에 **접근성 검사**(이름 없는 컨트롤, 글자 대비 WCAG AA, 터치 목표 32px)를 끼워 데스크톱 라이트·다크와 휴대폰 터치에서 돌렸다. 콘솔 오류·경고도 모았다. |
| 2 · 기능 시나리오 | 브라우저 테스트(114개)가 이미 덮는 흐름은 빼고 덮지 않는 곳을 손으로 확인했다. 망가진 링크 6종(`#puzzle=` `#replay=` `#rules=` `#daily=` 빈 값·모르는 키), 게임 중 R, 창 포커스 잃기, 휴대폰 세 기종의 보드·버튼 크기를 봤다. |
| 3 · 관점별 | 데스크톱·휴대폰 세로·가로·처음 온 사람 화면 47장을 찍어 봤다. 첫 화면, 게임, 일시정지, 결과, 설정 탭, 기록, 연습, 퍼즐, 업적, 퍼즐 만들기, CPU 대전이다. 네 사람의 흐름으로 걸었다: 처음 10분, 휴대폰으로 잠깐, 기록 노리는 사람, 퍼즐 만드는 사람. |

**결과 요약**
- 8가지 조합 모두 넘침·잘림·겹침 0건, 콘솔 오류 0건. 이름 없는 컨트롤 0건, 다크 대비 문제 0건.
- 새로 찾은 것은 **퍼즐 만들기 첫 화면**(열자마자 아래로 스크롤됨, 발 줄 배치)이 가장 크다.
- 나머지는 휴대폰 터치 목표, 휴대폰 보드 크기, 기록 노리는 사람을 위한 빠른 재시작 같은 다듬기다.

**한계:** Chromium에서만 봤다(Safari·Firefox 아님). 손맛(입력 지연, DAS 느낌)과 소리는 직접 느낄 수 없다.
G 항목 중 "직접 해 보고 확인해 주세요"라고 적은 것은 실제 기기에서 판단해 주세요.

심각도: **치명** = 못 쓰거나 잘못 씀 · **높음** = 크게 불편하거나 잃는 것이 있음 · **보통** = 거슬림·일관성 · **낮음** = 다듬기.
번호는 4차에 이어 붙이고, 게이머 관점은 G1부터 새로 센다.

## Part 1. 기능

| # | 심각도 | 기능 | 문제 · 근거 | 제안 |
|---|---|---|---|---|
| F39 | 높음 | 퍼즐 만들기 열기 | 열자마자 대화상자 몸통이 **315px 아래로 스크롤된 채** 뜬다. 이름·설명·시작 틀·목표·칠하기·높이가 모두 위로 밀려 안 보이고, 판 격자부터 보인다. 처음 만드는 사람은 목표·시작 틀이 있는 줄도 모른다. 원인: `js/ui/puzzle-editor.js:1071` `tiles[focusIndex].focus()`가 첫 칸으로 포커스를 옮기며 스크롤한다(데스크톱·휴대폰 같음). | `focus({ preventScroll: true })`로 바꾸고 몸통을 맨 위에서 연다. UI 검수에 "대화상자를 열면 몸통 scrollTop이 0"을 더한다. |
| F40 | 낮음 | `#daily=` 잘못된 코드 | 다른 링크(퍼즐·리플레이·규칙)는 못 읽으면 "링크의 …을 읽을 수 없었어요"라고 바로 알린다. 오늘의 도전만 `#daily=xx`처럼 깨진 코드에도 "받은 결과가 있어요. 겨루기를 누르면…"이라고 하고, 겨루기를 눌러야 실패를 알려 준다. | 열 때 코드를 먼저 풀어 보고, 못 읽으면 다른 링크와 같은 문구를 쓴다. |

기능 시나리오 중 문제없던 것: 망가진 `#puzzle=` `#replay=` `#rules=`와 빈 값(알림 후 첫 화면, 오류 없음), 창 포커스를 잃으면 일시정지, 일시정지 뒤 계속.

## 네 사람의 흐름에서 본 것

- **처음 10분(데스크톱):** 첫 화면 → 안내 → Sprint → 결과까지 막힘이 없다. 처음에는 카운트다운이 있고, 결과에서 R·Esc가 보인다. 휴대폰은 U60.
- **휴대폰으로 잠깐:** 터치 버튼 배치가 세로·가로 모두 손가락이 닿는 곳에 있고, 창을 떠나면 저절로 일시정지된다. 보드 크기는 G2.
- **기록 노리는 사람:** 최고 기록 대비, 구간, 리플레이, 장면 연습, 최고 기록과 달리기까지 갖췄다. 아쉬운 것은 재시작 두 번(G1)과 일시정지 중 보이는 판(G4).
- **퍼즐 만드는 사람:** 기능은 충분하다. 다만 열자마자 중요한 위쪽 설정이 안 보이고(F39), 닫기 자리가 어색하다(U54).
