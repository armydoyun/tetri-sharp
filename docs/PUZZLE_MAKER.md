# 퍼즐 만들기 개선 계획

> 다음 업데이트의 목표: "퍼즐 만들기"를 **만들기 좋게**, 받은 퍼즐을 **쓰기 좋게**.
> 오프라인 원칙은 그대로다. 서버·계정·외부 요청 없이 링크와 이 기기의 저장소(`localStorage`, 백업 파일)만 쓴다.

## 1. 만들기 좋게

### 1-1. 보드 편집 (가장 시급)

- [ ] **드래그로 칠하기**: 누른 칸의 반대 상태로 끌고 가는 칸을 모두 맞춘다(첫 칸이 빈 칸이면 채우기, 찬 칸이면 지우기).
      마우스·터치·펜을 Pointer Events 하나로. 터치에서는 보드 위 스크롤을 막는다(`touch-action: none`).
- [ ] **줄 단위 도구**
  - 한 줄 채우기·지우기(줄 머리를 누르거나 길게 누르기)
  - **구멍 하나 남긴 쓰레기 줄**: 열을 고르면 그 열만 빈 줄을 아래에 넣고 위로 민다
  - 판 전체 지우기(`confirmButton()`으로 두 번 눌러 확정)
  - 위·아래·좌우로 판 전체 밀기, 좌우 뒤집기(미러 퍼즐 만들기)
- [ ] **되돌리기·다시 하기**: 편집 기록 스택. `Ctrl+Z` / `Ctrl+Shift+Z`, 버튼도 둔다.
- [ ] **편집 높이 줄이기**: 20행을 다 보여 주면 칸이 작다. 실제로 쓰는 높이(기본 8행, 늘리기 가능)만 크게 보여 준다.
      보이지 않는 위쪽은 빈 칸으로 저장한다.
- [ ] **기존 퍼즐에서 시작**: 기본 퍼즐 단계나 받은 퍼즐을 "복사해서 편집"으로 연다.
- [ ] 칸 색: 지금은 회색 한 가지. 피스 색으로 칠하기는 보기용으로만(판정은 같다) — 우선순위 낮음.

### 1-2. 피스 순서

- [ ] 최대 개수 6 → **10개**로(링크 길이 여유 충분).
- [ ] 순서 안에서 **고른 자리에 넣기·빼기·끌어서 옮기기**. 지금은 마지막만 뺄 수 있다.
- [ ] 피스 버튼에 미니 모양 아이콘(`icons.js` SVG). 글자만 있는 I·J·L… 은 처음 보는 사람에게 어렵다.
- [ ] **다음 미리보기 개수**를 정할 수 있게(기본: 전부 보임). 숨기면 "앞을 모르고 푸는" 퍼즐.

### 1-3. 목표 고르기

기본 퍼즐에 이미 있는 목표를 만든 퍼즐에서도 쓴다(`js/modes/puzzles.js`의 `kind`와 `goal`).

- [ ] 판 비우기(퍼펙트 클리어) — 지금
- [ ] **T-spin Mini / Double / Triple**: 마지막 피스(T)로 해당 스핀
- [ ] **4줄 만들기**: 마지막 피스로 4줄
- [ ] **콤보 이어 가기**: 피스마다 한 줄 이상
- [ ] **N줄 지우기**: 피스를 다 쓰기 전에 N줄
- [ ] 목표마다 "마지막 피스로만 인정" 같은 조건은 기본 퍼즐 판정을 그대로 재사용한다(새 판정 코드를 만들지 않는다).

### 1-4. 규칙 고르기

- [ ] **홀드 켜고 끄기** (기본: 끔, 지금과 같음)
- [ ] **회전 방식**(SRS 등 `js/rules/rotation`): 회전 방식이 다르면 스핀이 되고 안 되는 자리가 달라진다.
- [ ] 나머지 규칙(중력·DAS 등)은 퍼즐에서 의미가 없으므로 담지 않는다. 퍼즐은 늘 중력 없음.
- [ ] 고른 규칙을 편집기 위에 한 줄로 보여 준다(예: "SRS · 홀드 켬 · T-spin Double").

### 1-5. 풀이 자동 확인

- [ ] 편집 중 **"풀 수 있는지 확인"** 버튼: `findFirstMove`로 길을 찾는다.
  - 풀 수 있음 → 시험 플레이 없이도 공유 가능하게 할지 결정 필요(아래 7. 결정할 것)
  - 못 풀어요 → "이 피스로는 판을 비울 수 없어요" 등 이유를 짧게
  - 시간 초과(`BUDGET`) → "너무 복잡해서 확인하지 못했어요. 시험 플레이로 확인해 주세요"
- [ ] 탐색이 무거우면 Web Worker로 돌려 화면이 멈추지 않게(빌드가 한 파일이므로 인라인 Worker).
- [ ] **풀이 보기**: 찾은 길을 한 수씩 보드에 겹쳐 보여 준다(만든 사람이 의도와 다른 풀이를 알아챌 수 있게).
- [ ] (선택) **풀이 개수·난이도 추정**: 풀이가 여러 개면 "쉬움", 하나뿐이면 "까다로움" 같은 표시.

### 1-6. 미리 막아 주기

- [ ] 칸 수 검사: 판 비우기인데 (빈 칸 수)가 (피스 수 × 4)와 맞지 않으면 바로 알려 준다.
- [ ] 떠 있는 줄이 다 찬 상태(이미 지워질 줄) 경고.
- [ ] 피스가 나올 자리가 막혀 있으면 경고(바로 게임 오버).

## 2. 쓰기 좋게

### 2-1. 내 퍼즐 목록

- [ ] 만든 퍼즐을 **이 기기에 저장**(`js/storage` 새 모듈, 키 `tetrisharp:customPuzzles`).
      이름, 만든 날, 마지막으로 고친 날, 풀었는지.
- [ ] 퍼즐 창에 **"내 퍼즐"** 칸: 플레이 · 편집 · 링크 복사 · 지우기(`confirmButton()`).
      줄은 `menuRow`로 만든다(`docs/DESIGN_SYSTEM.md` "컴포넌트").
- [ ] 백업 파일(`js/app/backup.js`)에 같이 넣고, 불러오기 때 같은 퍼즐은 합친다.
- [ ] 저장 개수 한도(예: 50개)와 한도에 닿았을 때 안내.

### 2-2. 받은 퍼즐

- [ ] 링크로 연 퍼즐을 **"받은 퍼즐"**로 목록에 남긴다(같은 코드면 하나로).
- [ ] 풀었는지·최소 피스 수·걸린 시간 기록.
- [ ] 받은 퍼즐을 "복사해서 편집" → 내 퍼즐로.

### 2-3. 제목·설명

- [ ] 퍼즐 이름(최대 24자)과 한 줄 설명(최대 60자). 링크에 담는다.
- [ ] 받은 쪽에서 게임 화면 목표 줄(`#mode-objective`)과 결과 화면에 보여 준다.
- [ ] 이름은 사용자가 쓴 글이므로 `textContent`로만 넣는다(HTML로 해석하지 않는다).

### 2-4. 플레이 흐름

- [ ] 만든 퍼즐에도 **"첫 수 보기"**(기본 퍼즐과 같은 버튼, 단축키 H).
- [ ] 결과 화면: 다시 풀기 · 편집(만든 사람만) · 내 퍼즐 목록으로.
- [ ] 받은 퍼즐을 풀면 "만든 사람에게 보낼 결과" 짧은 문구 복사(풀었는지, 첫 수 보기를 썼는지) — 선택.

### 2-5. 퍼즐 묶음 (나중에)

- [ ] 여러 퍼즐을 하나의 링크로(예: 5문제 세트). 링크 길이 한도 안에서.
- [ ] 묶음 진행도 표시.

## 3. 링크 형식 `2.`

지금 `1.<보드>.<피스>`는 목표·규칙·제목을 담지 못한다. 새 형식을 더하고 **`1.` 링크는 계속 연다**(Modern, 홀드 없음, 판 비우기로 해석).

```
#puzzle=2.<옵션>.<보드>.<피스>[.<제목·설명>]
```

- 옵션: 목표 종류, 홀드, 회전 방식, 미리보기 개수를 짧은 글자로(예: `pc-h0-srs-n5`). 모르는 값은 기본값으로.
- 보드: 쓰는 높이만 담아 짧게(높이 + hex). 빈 위쪽은 생략.
- 제목·설명: base64url(UTF-8). 길이 한도를 넘으면 자른다.
- 디코딩은 지금처럼 엄격하게: 한도 밖 길이, 모르는 글자, 다 빈 판은 거절하고 "링크의 퍼즐을 읽을 수 없었어요".
- 단위 테스트: `1.` 링크 하위 호환, `2.` 왕복(encode→decode), 망가진 코드 거절.

## 4. 화면·디자인 약속 (AGENTS.md)

- 버튼·세그먼트·스위치·입력·목록 줄은 `js/ui/components.js`로만. 편집기 보드 칸(`puzzle-editor-cell`)은 지금처럼 그리드 칸으로 두되
  크기·여백은 CSS 변수로.
- 목표·회전 방식 선택은 `segmented()` 또는 `dropdown()`, 홀드는 `toggle()`.
- 상태가 바뀌어도 자리 그대로: 경고·확인 결과 문구는 `notice-slot`처럼 높이를 남기는 칸에.
- 지우기·판 전체 지우기는 `confirmButton()`.
- 새 문구는 한국어로 쓰고 `t()`로 감싸 `js/i18n/en.js`에 영어를 더한다. 아이콘은 `icons.js` SVG.
- UI 검수(`tests/helpers/ui-audit.mjs`) 네 화면 크기에서 넘침·잘림이 없어야 한다. 편집기는 휴대폰 세로에서 특히 확인.

## 5. 단계 나누기 (추천 순서)

| 단계 | 내용 | 이유 |
|---|---|---|
| **1** | 드래그 칠하기, 줄 도구, 되돌리기, 편집 높이 줄이기, 피스 순서 편집·10개 | 만드는 수고가 가장 크게 줄어든다 |
| **2** | 풀이 자동 확인(+ 풀이 보기), 미리 막아 주기 | 못 푸는 퍼즐을 공유하는 일을 막는다 |
| **3** | 내 퍼즐·받은 퍼즐 목록, 제목·설명, 백업 | 만든 것을 계속 쓰게 된다 |
| **4** | 링크 `2.` + 목표·홀드·회전 방식 선택 | 3단계의 제목과 함께 형식을 한 번에 바꾼다 |
| 5 | 묶음, 난이도 추정, 피스 색 칠하기 | 있으면 좋은 것 |

3단계와 4단계는 링크 형식이 함께 바뀌므로 한 PR로 묶어도 된다.

## 6. 테스트 계획

- 단위
  - 링크 `1.`·`2.` 인코딩·디코딩, 하위 호환, 거절 사례
  - 편집 동작(칠하기·줄 넣기·밀기·뒤집기·되돌리기)을 DOM 없는 순수 함수로 떼어 테스트
  - 목표별 판정이 기본 퍼즐과 같은 함수를 쓰는지
  - 풀이 확인: 풀 수 있는 판·없는 판·시간 초과
  - 저장 목록: 추가·수정·삭제·한도·백업 합치기
- 브라우저
  - 드래그로 칠한 뒤 시험 플레이 → 풀기 → 링크 복사 → 새 창에서 열기
  - 목표·홀드를 바꾼 퍼즐이 받는 쪽에서 같은 규칙으로 열린다
  - 내 퍼즐 목록에서 편집·지우기(두 번 눌러 확정)
  - 휴대폰 세로·가로에서 편집기 UI 검수
