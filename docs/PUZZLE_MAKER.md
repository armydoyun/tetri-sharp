# 퍼즐 만들기 개선 계획

> 다음 업데이트의 목표: "퍼즐 만들기"를 **만들기 좋게**, 받은 퍼즐을 **쓰기 좋게**.
> 방향: 규칙을 갈아끼우는 Tetri#의 장점을 그대로 쓰는 **전문 편집기**. 단, 처음 온 사람은 지금처럼 바로 만들 수 있게
> **기본 화면 / 고급 설정** 두 층으로 나눈다.
> 오프라인 원칙은 그대로다. 서버·계정·외부 요청 없이 링크와 이 기기의 저장소(`localStorage`, 백업 파일)만 쓴다.

## 1. 정한 것

| 주제 | 결정 |
|---|---|
| 편집기 구성 | **기본 화면**(보드·피스 순서·목표) + 접힌 **고급 설정**(규칙 전체·중력·미리보기·처음 홀드 피스). 바꾼 고급 항목은 접힌 상태에서도 한 줄로 보인다 |
| 시작 | **시작 틀**에서 고른다: 빈 판, T-스핀 자리, 4줄 우물, 기본 퍼즐 N단계 복사, 받은 퍼즐 복사 |
| 피스 최대 개수 | 링크 길이와는 상관없다(피스 하나 = 한 글자). 판 높이에 맞춘 **넉넉한 안전선 50개**만 둔다 |
| 자동 확인 한도 | 탐색기는 **되는 만큼만**. 예산 안에 못 찾으면 "너무 길어서 자동으로 확인하지 못했어요. 시험 플레이로 직접 풀어 주세요" |
| 규칙 범위 | **규칙 전체**를 퍼즐에 담는다. 링크에는 **바탕 규칙 + 다른 항목만** 짧게(대부분 링크 100자 안팎) |
| 중력 | **없음(기본) / 20G / 규칙대로** 세 가지 중에 고른다 |
| 공유 조건 | 자동 확인으로 **풀 수 있다고 나오면 시험 플레이 없이도 공유**할 수 있다. 직접 풀어 본 퍼즐에는 "직접 풀어 봤어요" 표시를 따로 단다. 자동 확인이 안 되는 퍼즐(규칙대로 중력, 예산 초과)은 **직접 풀어야** 공유할 수 있다 |
| 받은 퍼즐 | 링크로 열면 **자동으로 "받은 퍼즐" 목록에 남긴다**. 지우기 쉽게 |
| 이번 범위 | **판 + 피스 + 목표**, **규칙 전체 + 중력 세 가지**, **목록·링크**까지. 나머지는 [7. 나중에](#7-나중에) |

## 2. 만들기 좋게

### 2-1. 보드 편집 (가장 시급)

- [ ] **드래그로 칠하기**: 누른 칸의 반대 상태로 끌고 가는 칸을 모두 맞춘다(첫 칸이 빈 칸이면 채우기, 찬 칸이면 지우기).
      마우스·터치·펜을 Pointer Events 하나로. 보드 위에서는 스크롤을 막는다(`touch-action: none`).
- [ ] **줄 단위 도구**
  - 한 줄 채우기·지우기
  - **구멍 하나 남긴 쓰레기 줄**: 열을 고르면 그 열만 빈 줄을 아래에 넣고 위로 민다
  - 판 전체 지우기(`confirmButton()`으로 두 번 눌러 확정)
  - 위·아래·좌우로 판 전체 밀기, 좌우 뒤집기(미러 퍼즐)
- [ ] **되돌리기·다시 하기**: 편집 기록 스택. `Ctrl+Z` / `Ctrl+Shift+Z`, 버튼도 둔다. 보드·피스·목표·고급 설정 변경 모두 포함.
- [ ] **편집 높이 줄이기**: 20행을 다 보여 주면 칸이 작다. 실제로 쓰는 높이(기본 8행, 늘리기 가능)만 크게 보여 준다.
      보이지 않는 위쪽은 빈 칸으로 저장한다.
- [ ] **시작 틀**(1. 정한 것): 편집기를 열면 고른다. 기본 퍼즐 단계·받은 퍼즐은 "복사해서 편집"으로.

### 2-2. 피스 순서

- [ ] 최대 개수 6 → **50개**(안전선). 순서 표시는 길어지면 줄바꿈되는 칩 목록으로.
- [ ] 순서 안에서 **고른 자리에 넣기·빼기·끌어서 옮기기**. 키보드로도(고른 칩 좌우 이동, Delete로 빼기).
- [ ] 피스 버튼에 미니 모양 아이콘(`icons.js` SVG). 글자만 있는 I·J·L…은 처음 보는 사람에게 어렵다.

### 2-3. 목표 고르기 (기본 화면)

기본 퍼즐에 이미 있는 목표를 만든 퍼즐에서도 쓴다(`js/modes/puzzles.js`의 `kind`와 `goal`).

- [ ] 판 비우기(퍼펙트 클리어) — 지금
- [ ] **T-spin Mini / Double / Triple**: 마지막 피스(T)로 해당 스핀
- [ ] **4줄 만들기**: 마지막 피스로 4줄
- [ ] **콤보 이어 가기**: 피스마다 한 줄 이상
- [ ] **N줄 지우기**: 피스를 다 쓰기 전에 N줄
- [ ] 판정은 기본 퍼즐과 같은 함수를 쓴다(새 판정 코드를 만들지 않는다).

### 2-4. 고급 설정 (접힘)

규칙 편집 화면(`js/ui/rules.js`)의 항목을 그대로 쓴다. 바탕 규칙(Modern·Retro·Arcade·내 규칙)을 고르고 항목을 바꾼다.

- [ ] **퍼즐에 영향이 있는 항목**: 회전 방식, T-스핀 판정, 홀드, 미리보기 개수, 하드 드롭, 고스트, 미리 회전·홀드(IRS·IHS), 고정 방식(lock).
- [ ] **퍼즐에서 쓰이지 않는 항목**(랜덤 방식 — 피스 순서는 퍼즐이 정한다, 점수 방식 등)은 담되 흐리게 보이고 "퍼즐에서는 쓰이지 않아요"라고 적는다.
- [ ] **처음 홀드 피스**: 홀드가 켜져 있으면 처음부터 홀드 칸에 들어 있을 피스(없음 가능).
- [ ] 접힌 머리에 바꾼 항목 요약 한 줄(예: "고급: SRS · 20G · 홀드 켬 · 미리보기 3").

### 2-5. 중력 세 가지

| 선택 | 어떤 퍼즐 | 자동 확인 · 첫 수 보기 |
|---|---|---|
| **없음**(기본) | 생각하는 퍼즐. 시간 압박 없음 | ✅ |
| **20G** | 피스가 나오자마자 바닥까지. 바닥을 따라 미끄러지거나 회전으로 턱을 넘어야 한다 | ✅ 탐색기에 "늘 바닥" 조건을 더한다 |
| **규칙대로** | 규칙의 중력·고정 시간 그대로. 시간 압박 퍼즐 | ❌ 푸는 사람의 DAS·ARR과 손 빠르기에 달려 있어 확인할 수 없다 |

- [ ] 엔진: `makePuzzleMode`의 `gravityFor`를 퍼즐 설정에 따라 0 / 20G / 규칙 값으로.
- [ ] 탐색기(`reachable`): 20G에서는 매 이동·회전 뒤 바닥까지 내린 자리만 상태로 둔다. 단위 테스트로 엔진과 같은 자리에 닿는지 확인한다.
- [ ] "규칙대로"는 첫 수 보기 버튼을 `disabled`로(자리는 남긴다), 결과 화면에 "만든 사람의 조작 설정 기준으로 확인한 퍼즐"이라고 적는다.

### 2-6. 풀이 자동 확인

- [ ] 편집 중 **"풀 수 있는지 확인"** 버튼: `findFirstMove`로 길을 찾는다.
  - 풀 수 있음 → 링크 공유를 켠다(1. 정한 것)
  - 못 풀어요 → "이 피스로는 판을 비울 수 없어요" 등 이유를 짧게
  - 예산 초과 → "너무 길어서 자동으로 확인하지 못했어요. 시험 플레이로 직접 풀어 주세요"
- [ ] 탐색이 무거우면 Web Worker로 돌려 화면이 멈추지 않게(빌드가 한 파일이므로 인라인 Worker). 확인 중에는 취소 버튼.
- [ ] **풀이 보기**: 찾은 길을 한 수씩 보드에 겹쳐 보여 준다(의도와 다른 풀이를 알아챌 수 있게).
- [ ] 편집하면 확인 결과는 지운다(지금 `cleared`를 지우는 것과 같은 방식).

### 2-7. 미리 막아 주기

- [ ] 칸 수 검사: 판 비우기인데 (빈 칸 수)가 (피스 수 × 4)와 맞지 않으면 바로 알려 준다.
- [ ] 이미 다 찬 줄(시작하자마자 지워질 줄) 경고.
- [ ] 피스가 나올 자리가 막혀 있으면 경고(바로 게임 오버).
- [ ] 경고 문구는 높이를 남기는 칸(`notice-slot`)에 둔다.

## 3. 쓰기 좋게

### 3-1. 내 퍼즐 목록

- [ ] 만든 퍼즐을 **이 기기에 저장**(`js/storage` 새 모듈, 키 `tetrisharp:customPuzzles`).
      이름, 만든 날, 마지막으로 고친 날, 확인 상태(자동 확인 / 직접 풀어 봄 / 확인 안 됨).
- [ ] 퍼즐 창에 **"내 퍼즐"** 칸: 플레이 · 편집 · 링크 복사 · 지우기(`confirmButton()`). 줄은 `menuRow`.
- [ ] 백업 파일(`js/app/backup.js`)에 같이 넣고, 불러오기 때 같은 퍼즐(같은 코드)은 합친다.
- [ ] 저장 개수 한도(예: 100개)와 한도에 닿았을 때 안내.

### 3-2. 받은 퍼즐

- [ ] 링크로 연 퍼즐을 **자동으로 "받은 퍼즐"에 남긴다**(같은 코드면 하나로). 목록에서 바로 지울 수 있게.
- [ ] 풀었는지 · 첫 수 보기를 썼는지 · 걸린 시간 기록.
- [ ] "복사해서 편집" → 내 퍼즐로.

### 3-3. 제목·설명

- [ ] 퍼즐 이름(최대 24자)과 한 줄 설명(최대 60자). 링크에 담는다.
- [ ] 받은 쪽 게임 화면 목표 줄(`#mode-objective`)과 결과 화면에 보여 준다.
- [ ] 사용자가 쓴 글이므로 `textContent`로만 넣는다(HTML로 해석하지 않는다).

### 3-4. 플레이 흐름

- [ ] 만든 퍼즐에도 **"첫 수 보기"**(기본 퍼즐과 같은 버튼, 단축키 H). "규칙대로" 중력에서는 `disabled`.
- [ ] 결과 화면: 다시 풀기 · 편집(내 퍼즐일 때) · 목록으로.
- [ ] 게임 화면 정보 칸에 바뀐 규칙 요약 한 줄(예: "20G · 홀드 켬") — 받은 사람이 규칙이 다르다는 걸 알 수 있게.

## 4. 링크 형식 `2.`

지금 `1.<보드>.<피스>`는 목표·규칙·제목을 담지 못한다. 새 형식을 더하고 **`1.` 링크는 계속 연다**(Modern, 홀드 없음, 중력 없음, 판 비우기).

```
#puzzle=2.<설정>.<보드>.<피스>[.<제목·설명>]
```

- **설정**: 목표 · 중력(없음/20G/규칙대로) · 바탕 규칙 id · **바탕 규칙과 다른 규칙 항목만** · 처음 홀드 피스.
  항목마다 짧은 기호(예: `g20`, `h1`, `p3`, `r:srs`)를 정해 표로 남긴다. 모르는 기호는 무시하고 기본값으로.
  - 규칙 링크(`#rules=`)는 규칙 전체를 JSON으로 담아 약 420자다. 퍼즐 링크는 차이만 담아 **대부분 100자 안팎**으로.
  - 바탕이 "내 규칙"이면 받는 쪽에는 그 규칙이 없으므로, 가장 가까운 기본 규칙 + 차이로 바꿔 담는다.
  - 받은 값은 `sanitizeRuleBody`를 거쳐 허용된 값으로만 들어온다.
- **보드**: 쓰는 높이만 담아 짧게(높이 + hex). 빈 위쪽은 생략.
- **피스**: 한 글자씩, 최대 50개.
- **제목·설명**: base64url(UTF-8). 길이 한도를 넘으면 자른다.
- 디코딩은 지금처럼 엄격하게: 한도 밖 길이, 모르는 글자, 다 빈 판은 거절하고 "링크의 퍼즐을 읽을 수 없었어요".

## 5. 화면·디자인 약속 (AGENTS.md)

- 버튼·세그먼트·스위치·입력·목록 줄은 `js/ui/components.js`로만. 편집기 보드 칸(`puzzle-editor-cell`)은 지금처럼 그리드 칸으로 두되
  크기·여백은 CSS 변수로.
- 목표는 `segmented()` 또는 `dropdown()`, 중력 세 가지는 `segmented()`, 홀드 등 켜고 끄기는 `toggle()`.
- 고급 설정을 펴고 접을 때 기본 화면의 요소가 움직이지 않게(고급 설정은 아래에 붙는다).
- 상태가 바뀌어도 자리 그대로: 경고·확인 결과 문구는 높이를 남기는 칸에, 쓸 수 없는 버튼은 `disabled`.
- 지우기·판 전체 지우기는 `confirmButton()`.
- 새 문구는 한국어로 쓰고 `t()`로 감싸 `js/i18n/en.js`에 영어를 더한다. 아이콘은 `icons.js` SVG.
- UI 검수(`tests/helpers/ui-audit.mjs`) 네 화면 크기에서 넘침·잘림이 없어야 한다. 편집기는 휴대폰 세로에서 특히 확인.

## 6. 단계 나누기

| 단계 | 내용 | 이유 |
|---|---|---|
| **1** | 드래그 칠하기, 줄 도구, 되돌리기, 편집 높이 줄이기, 피스 순서 편집·50개, 시작 틀 | 만드는 수고가 가장 크게 줄어든다 |
| **2** | 풀이 자동 확인(+ 풀이 보기, Worker), 미리 막아 주기, 자동 확인으로 공유 | 못 푸는 퍼즐을 공유하는 일을 막는다 |
| **3** | 목표 고르기, 고급 설정(규칙 전체), 중력 세 가지(20G 탐색 포함), 링크 `2.` | 형식이 함께 바뀌므로 한 묶음으로 |
| **4** | 내 퍼즐·받은 퍼즐 목록, 제목·설명, 백업, 플레이 흐름 정리 | 만든 것을 계속 쓰게 된다 |

단계마다 PR 하나. 각 PR은 AGENTS.md의 확인 다섯 가지를 모두 통과한다.

## 7. 나중에

이번 범위 밖. 퍼즐이라기보다 "작은 모드 만들기"에 가까워 판정·테스트가 크게 늘어나는 것들.

- 제한 시간 퍼즐
- 목표 여러 개(예: T-스핀 더블 뒤 판 비우기)
- 올라오는 쓰레기 줄
- 여러 퍼즐을 하나의 링크로 묶기(세트)와 묶음 진행도
- 풀이 개수로 난이도 추정
- 피스 색으로 칠하기(보기용)

## 8. 테스트 계획

- 단위
  - 링크 `1.`·`2.` 인코딩·디코딩, 하위 호환, 거절 사례, 규칙 차이 왕복(바탕 + 차이 → 같은 규칙)
  - 편집 동작(칠하기·줄 넣기·밀기·뒤집기·되돌리기)을 DOM 없는 순수 함수로 떼어 테스트
  - 목표별 판정이 기본 퍼즐과 같은 함수를 쓰는지
  - 풀이 확인: 풀 수 있는 판·없는 판·예산 초과, 20G에서 엔진과 같은 자리에 닿는지
  - 저장 목록: 추가·수정·삭제·한도·백업 합치기
- 브라우저
  - 드래그로 칠한 뒤 자동 확인 → 링크 복사 → 새 창에서 열기 → 받은 퍼즐 목록에 남는다
  - 고급 설정(20G·홀드)을 바꾼 퍼즐이 받는 쪽에서 같은 규칙으로 열린다
  - "규칙대로" 중력은 직접 풀어야 공유가 켜지고, 첫 수 보기가 꺼져 있다
  - 내 퍼즐 목록에서 편집·지우기(두 번 눌러 확정)
  - 휴대폰 세로·가로에서 편집기 UI 검수, 고급 설정을 펴고 접어도 기본 화면이 움직이지 않는다
