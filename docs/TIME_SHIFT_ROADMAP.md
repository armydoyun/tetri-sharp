# Tetri# 시간차 구현 로드맵

**시간차**는 첫 번째 플레이의 배치를 되감은 뒤, 과거의 블록과 현재의 블록을 같은 보드에 쌓는 모드다. 첫 번째에 남겨 둔 빈칸과 두 번째에 만든 받침대가 함께 해법이 된다. 같은 과거 수라도 현재 보드에 따라 다른 높이에 착지한다.

첫 PR은 첫 스테이지를 처음부터 끝까지 플레이할 수 있는 버전이다. 첫 출시에는 공식 스테이지 5개, 이어서 하기, 완료 진행도 및 백업을 포함한다. 후속 업데이트에서는 친구가 내 첫 번째 플레이를 이어서 완성하는 공유 도전을 제공한다.

## 출시 구현

첫 화면에서 시간차를 열면 **한 수 체험**, **공식 스테이지**, **도전 코드 열기**를 고를 수 있다. 체험에서는 준비된 과거 O와 현재 O로 한 줄을 완성한다. 현재 O를 과거 O의 자리에 놓을 때와 나란히 놓을 때의 차이를 점선과 결과로 확인할 수 있다. 공식 스테이지 성공 화면의 **다음 단계**는 다음 판의 첫 번째 플레이를 연다.

이어서 하기는 첫 번째 플레이, 되감기 대기 화면, 되감기 직후와 두 번째 플레이를 복원한다. 첫 합주 구현 PR의 버전 필드가 없는 저장도 읽는다. 완료 진행도는 단계 ID로 저장하며, 시간차 항목이 없는 이전 백업을 열어도 기존 완료 단계가 남는다.

공식 5단계의 블록과 판은 모드에 정의하고, 검증에 쓰는 풀이 입력은 테스트에서 공유한다. [스테이지 정의](../js/modes/time-shift.js) · [풀이 입력](../tests/helpers/time-shift-solutions.mjs)

## 친구 도전

공식 스테이지에서 6수를 기록하거나 두 번째 플레이를 성공하면 결과 화면에서 링크나 코드를 복사할 수 있다. 받은 사람은 목표를 확인한 뒤 같은 시작 보드와 과거 6수로 두 번째 플레이부터 시작한다. 링크에는 단계 ID와 버전, 과거 블록의 열과 회전만 담는다. 단일 HTML 배포본에서는 복사한 코드를 시간차 메뉴에 붙여 넣을 수 있다.

받은 도전은 새로고침 후 이어서 하거나 같은 기록으로 재도전할 수 있다. 체험과 친구 도전 완료는 공식 스테이지 진행도에 포함되지 않는다. [공유 코드](../js/modes/time-shift-share.js)

## 플레이 규칙

| 구간 | 동작 | 확정할 상태 |
| --- | --- | --- |
| 첫 번째 플레이 | 스테이지가 정한 순서의 블록 6개를 놓는다. 줄 삭제는 이 플레이의 보드에 적용된다. | 각 고정 시점의 블록 종류, 열 좌표, 회전 상태를 순서대로 기록한다. |
| 되감기 | 여섯 번째 고정이 끝나면 시작 보드를 복원하고 두 번째 순서의 블록을 준비한다. | 첫 번째 플레이의 6수를 보존한다. 보드와 줄 삭제 결과, 목표 카운터는 두 번째 플레이의 초기 상태로 바꾼다. |
| 두 번째 플레이 | 현재 블록을 하나 놓을 때마다 대응하는 과거 블록 하나가 위에서 수직 낙하한다. 최대 6턴을 진행한다. | 과거 블록의 열과 회전은 기록을 따르고, 착지 높이는 현재 보드에서 계산한다. |
| 결과 | 한 턴을 완전히 처리한 뒤 스테이지 목표를 판정한다. 마지막 턴까지 목표를 충족하지 못하면 실패한다. | 단계 완료, 줄 삭제 주체, 실패가 발생한 턴과 원인을 기록한다. |

공식 스테이지는 두 플레이의 블록 순서를 미리 정하고, 자동 낙하와 홀드 없이 시작한다. 시작 보드, 좌표 기준, 회전 규칙, 진입 위치는 스테이지마다 고정한다. 과거 블록은 좌우 이동이나 벽차기 없이 기록된 자세로 떨어진다. 경로가 막히면 장애물 위에 착지하고, 진입 위치부터 막혀 있으면 해당 턴에 실패한다.

### 두 번째 플레이의 한 턴

1. 현재 블록을 고정하고 완성된 줄을 삭제한다.
2. 갱신된 보드에서 같은 턴 번호의 과거 블록이 진입할 수 있는지 검사한다.
3. 진입할 수 있으면 가장 아래로 떨어뜨려 고정하고, 완성된 줄을 다시 삭제한다.
4. 현재 블록과 과거 블록의 삭제 결과를 구분해 목표를 판정한다.
5. 성공·실패가 확정되면 결과로 이동한다. 계속할 수 있으면 다음 현재 블록과 과거 수를 준비한다.

과거 블록의 진입 실패가 발생한 턴은 목표 성공으로 처리하지 않는다. 퍼펙트 클리어 스테이지는 여섯 번째 과거 블록 처리까지 마친 보드가 비어 있어야 성공한다. **두 번째 플레이 다시 하기**는 같은 시작 보드와 과거 6수로 복귀한다. **처음부터 다시 하기**는 첫 번째 플레이로 돌아가 새 기록을 만든다.

## 화면과 조작

- 첫 화면의 시간차 메뉴에서 한 수 체험이나 공식 스테이지를 선택한다. 보드 주변에 현재 플레이와 진행 수를 표시해 두 플레이를 구분한다.
- 두 번째 플레이에서 현재 블록의 기존 고스트와 다음 과거 블록의 예상 착지를 함께 표시한다. 과거 블록은 반투명 윤곽을 사용해 색이 없어도 구분할 수 있게 한다.
- 예상 착지는 **지금 위치에서 현재 블록을 내려놓는 경우**를 기준으로 한다. 현재 블록의 이동·회전 후 예상 고정과 줄 삭제를 반영해 다시 계산한다. 진입이 막힌 경우에는 착지 대신 막힌 상태를 알린다.
- 되감기와 과거 블록의 낙하를 화면에서 구분할 수 있게 한다. 동작 줄이기 환경에서는 상태 전환과 최종 위치를 바로 표시한다.
- 실패 화면에는 실패 턴과 이유를 남긴다. 재도전 버튼 두 개는 복원 범위가 이름만으로 구분되게 하고, 완료한 판에서는 다음 단계로 이동할 수 있게 한다.
- 키보드·터치·게임패드의 기존 조작을 사용한다. 모바일 세로·가로에서 보드, 예상 착지 표시, 조작 영역이 함께 보여야 한다. 컨트롤과 번역은 기존 저장소 규칙을 따른다.

## 공식 스테이지 5개

| 단계 | 목표 | 배울 발상과 제작 검증 |
| --- | --- | --- |
| **1. 첫 합주** | 두 플레이의 블록으로 한 줄을 완성한다. | 첫 번째에 남긴 공간을 두 번째에 채운다. 같은 과거 수로 현재 배치만 바꿨을 때 성공과 실패가 갈리는 예를 준비한다. |
| **2. 먼저 지워야 열리는 길** | 현재 블록의 줄 삭제로 과거 블록이 더 아래에 착지하게 한다. | 현재 블록의 삭제가 먼저 반영되는 것을 보여 준다. 같은 과거 수를 삭제 전 보드에 떨어뜨렸을 때는 다른 높이에 착지하는지 확인한다. |
| **3. 받침대** | 현재 블록으로 과거 블록을 높은 자리에 받아 목표 줄을 완성한다. | 장애물을 해법으로 사용한다. 받침이 없을 때의 실패와 받침을 놓았을 때의 성공을 모두 재현한다. |
| **4. 한 턴에 두 번** | 한 턴 안에서 현재 블록과 과거 블록이 각각 줄을 삭제한다. | 첫 삭제가 두 번째 삭제의 경로를 연다. 두 삭제가 같은 턴의 별도 원인으로 기록되는지 확인한다. |
| **5. 빈 판으로 돌아가기** | 두 번째 플레이의 마지막 과거 블록 처리 후 퍼펙트 클리어를 달성한다. | 첫 번째와 두 번째 배치가 함께 맞아야 한다. 총 12개 블록의 48칸과 시작 보드의 칸 수 합이 보드 너비의 배수인지 확인한 뒤, 실제 입력으로 가능한 풀이를 검증한다. |

각 스테이지에 고정 시작 보드와 두 블록 순서, 목표 판정, 실제 조작으로 재현하는 성공 풀이를 둔다. 3~5단계에서는 두 번째 순서만 바꾸는 것과 첫 번째 배치를 다시 짜는 것의 차이가 플레이에 드러나는지 확인한다. **첫 번째 기록을 다시 설계하고 싶어지는가**를 관찰한 뒤 난도를 높인다.

## 구현 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| **1. 한 판 프로토타입** | 첫 스테이지 데이터, 배치 기록, 되감기, 과거 블록 낙하, 결과를 연결한다. | 게임의 첫 화면에서 진입해 한 판을 끝까지 플레이할 수 있고, 같은 과거 수가 현재 배치에 따라 다른 결과를 낸다. |
| **2. 예상 착지와 재도전** | 턴 처리 규칙을 예상 착지와 실제 플레이 양쪽에서 사용한다. 두 종류의 재도전을 연결한다. | 이동·회전·줄 삭제·진입 막힘에서 예상과 실제가 일치한다. 두 번째 플레이만 다시 하면 기록한 6수가 그대로다. **1~2단계를 첫 PR 범위로 삼는다.** |
| **3. 플레이 흐름과 입력** | 플레이 단계 안내, 실패 피드백, 다음 단계, 키보드·터치·게임패드 조작과 동작 줄이기를 검수한다. | 처음 보는 플레이어가 별도 문서 없이 되감기와 자동 낙하를 이해하고, 실패 후 원하는 범위로 다시 시도한다. |
| **4. 공식 스테이지 확장** | 스테이지 2~5의 보드와 목표를 제작하고 실제 입력으로 풀이를 검증한다. | 5개 모두 정상 입력 경로로 풀 수 있고, 각 스테이지의 목표 판정이 의도대로 동작한다. |
| **5. 저장·복원·백업** | 이어서 하기와 완료 진행도를 연결하고, 공식 스테이지 버전과 저장 상태를 함께 검증한다. | 첫 번째 플레이 도중, 되감기 직후, 두 번째 플레이 도중에 새로고침해도 같은 판을 복원한다. 완료 진행도는 백업에서 복원되고 예전 백업도 열린다. |
| **6. 출시 검수** | 전체 검사, 단일 HTML·Pages 빌드, 오프라인 실행, 언어와 화면 크기별 검수를 진행한다. | 공식 5개 스테이지를 메뉴에서 끝까지 완주할 수 있고 기존 모드의 회귀 검사와 필수 CI가 통과한다. |

### 엔진과 저장소 연결

- 기존 엔진의 고정 후 처리 지점을 먼저 검토한다. 현재 블록의 줄 삭제 직후, 다음 피스가 나오기 전에 과거 블록을 처리해야 한다. 현재 블록이 직접 지운 줄과 과거 블록이 지운 줄을 이벤트에서 구분한다. [엔진 구현](../js/core/engine.js)
- 예상 착지는 보드 사본에서 계산한다. 실제 턴과 낙하·충돌·줄 삭제 규칙을 재사용하고, 계산 결과를 화면에 표시하는 일은 렌더러에서 맡는다. [보드 구현](../js/core/board.js)
- 이어서 하기는 기존 입력 일지 복원 방식을 우선 검토한다. 스테이지 ID와 버전, 플레이 단계, 과거 수와 다음에 소비할 순번을 검증 대상에 포함한다. 되감기를 한 번만 적용하도록 저장 시점은 턴 경계에 맞춘다. 복원 중 불일치나 잘못된 저장을 만나면 이유를 안내한다. [이어하기 흐름](../js/app/run-saver.js) · [입력 일지](../js/storage/suspended-run.js)
- 스테이지 완료는 ID별로 저장한다. 같은 스테이지를 여러 번 완료해도 진행도는 한 번만 쌓인다. 공식 스테이지의 풀이에 영향을 주는 보드나 블록 순서를 수정할 때는 기존 진행 중인 판을 어떻게 다룰지 버전과 함께 검토한다. [백업 구현](../js/storage/backup.js)
- 첫 출시 모드는 서버·계정 없이 오프라인에서 실행한다. 기록 경쟁이나 공유 코드와 연동하기 전에 공식 스테이지와 재도전 흐름을 먼저 완성한다. [기존 개발 계획](PLAN.md) · [디자인 시스템](DESIGN_SYSTEM.md)
